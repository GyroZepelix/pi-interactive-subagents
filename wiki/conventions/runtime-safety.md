# Runtime Safety Conventions

## Tool and extension isolation

New named Pi profile launches use `--no-extensions --no-builtin-tools` and do not use strict `--tools`. Explicit extension order is runtime control first, optional spawning control second, required built-in codemode/tool-search support, protected filtered MCP control when granted, canonical profile extensions in resolved order, and tool-free capability activation last (`pi-extension/subagents/index.ts`).

Validated `builtin-tools` and versioned MCP support state cross the child boundary through private package-owned environment values. The trailing activation control enables selected built-ins, required support, and tools registered by declared profile extensions while excluding MCP-control-owned indirect and hidden tools from blanket activation. Pi-native direct MCP and resource tools retain their configured exposure. Declared extensions remain trusted executable grants, not per-tool sandboxes (`pi-extension/subagents/subagent-capability-activation.ts`).

The protected MCP control re-reads exact canonical source entries and verifies their semantic digests before registering them through Pi's public MCP factory. Its config loader is deliberately empty, so unselected global/project servers never connect or contribute tools, resources, instructions, descriptions, or prompt metadata. Selected config bodies and resolved credentials are not copied into the capability channel. Selected names are reserved before trusted profile extensions load; differently named extension registrations remain allowed (`pi-extension/subagents/mcp-config.ts`, `pi-extension/subagents/subagent-mcp-control.ts`, `test/integration/mcp-capability.test.ts`).

For model-provider extensions in restricted profiles, `builtin-tools` constrains only Pi's built-in surface. Audit both tools registered with Pi and the provider's internal subprocess or protocol path; hiding registered tools does not prevent a provider from executing native file or shell operations itself. A read-only provider must reject its native mutating operations and bridge only the profile's active Pi tools (`spec/archive/260909-1928-create-global-scout-researcher-and-worker-profiles/verification.md`).

Match provider verification to the real child environment. A non-TTY SDK session can miss TTY-gated registrations that appear in tmux panes, so inspect the applicable TTY branch or run a TTY-equivalent check before claiming a provider adds no tools (`spec/archive/260909-1928-create-global-scout-researcher-and-worker-profiles/verification.md`).

Pi 0.87.0 dispatches lifecycle handlers in extension load order. Keep protected tool registration controls first so ordinary profile collisions cannot replace framework tools, and keep the tool-free activation control last so it observes same-event profile registrations before the next model request. Do not merge these roles without re-verifying Pi's lifecycle semantics (`package.json`, `spec/archive/260909-1952-profile-extension-loading/plan.md`, Decision D16).

Resolved profile extension files are preflighted before pane creation. This package's spawning extension is reserved: it is rejected from the profile slot without non-empty `subagent_agents`, then filtered and loaded once in the protected spawning slot when granted (`pi-extension/subagents/index.ts`).

Every spawn must name a valid discoverable agent selected from the active trusted context. Child commands always override `PI_SUBAGENT_ALLOWED` with the profile's exact nested targets; a present empty value means deny all, while an undefined value is reserved for an unrestricted top-level process (`pi-extension/subagents/agents.ts`, `pi-extension/subagents/index.ts`).

AGY profiles use a separate native boundary: a dedicated parent-session artifact workspace contains one generated primary agent with exactly the translated read tools, `mainAgent: true`, and `subagent: false`. Launch keeps the child cwd as the process workspace and adds the generated-agent root plus the distinct resolved parent Pi cwd. It never derives roots from task text, profile prose, referenced paths, or model output, and never passes `--dangerously-skip-permissions`. Default prompt-free workspace reads remain subject to explicit user AGY permission overrides; reported denied actions fail with bounded action evidence, the run's workspace roots, a remedy, and bounded stderr (`pi-extension/subagents/agy.ts`, `pi-extension/subagents/index.ts`).

AGY read reach beyond its workspaces depends on an operator-managed global policy in `~/.gemini/antigravity-cli/settings.json`: `permissions.allow` with `read_file(*)` and `permissions.deny` with `write_file(*)` plus absolute secret paths. Never add `--add-dir /` or permission bypass instead: added workspaces are writable and the runtime tool inventory is not limited to the generated agent. The extension never writes AGY settings; it only reads that one file and appends a non-blocking warning to AGY launch and resume acknowledgments when the two rules are absent. The policy is global (it also disables interactive AGY file writes), and in-repository secrets stay readable because AGY path globs are unsupported (`pi-extension/subagents/agy.ts`, `pi-extension/subagents/index.ts`, `README.md`).

On AGY 1.4.7, explicit deny-rule matches (including `write_file(*)` and secret-path read denies) reach the model as tool errors, are absent from `denied_actions`, and leave the envelope `SUCCESS`; only headless soft-denials populate `denied_actions`. The package therefore fails runs only for soft-denials. When an AGY review or scout result could be missing required evidence, inspect the response text for permission errors instead of trusting `SUCCESS` alone (`pi-extension/subagents/agy.ts`, `spec/archive/261025-0909-enable-read-anywhere-agy-subagents-via-operator-permission-policy/verification.md`).

## Model-chain safety

A chain prepares all shared capabilities, target-local extension paths, lifecycle controls, and required external executables before pane creation. Attempts run sequentially and receive only the original task plus shared role body; output, reasoning, tool transcripts, and provider conversation state never cross attempts. Shared built-ins are read-only, while declared Pi target extensions remain full trusted executable grants (`pi-extension/subagents/agents.ts`, `pi-extension/subagents/index.ts`).

Exhaustion classification accepts durable quota/usage/subscription/billing/budget/credit wording plus bare terminal 429 and resource-exhausted variants. It receives only structured terminal provider evidence: the final settled Pi assistant error or a valid AGY terminal `ERROR` envelope's structured error. Never classify formatted diagnostics, stderr-only malformed AGY output, denied actions, cancellation, interruption, or pane loss. Fixed bounded reasons prevent raw payload, task, stderr, or credentials from entering provenance. Bare 429 and resource exhaustion intentionally accept temporary-throttling false positives (`pi-extension/subagents/model-chain.ts`, `pi-extension/subagents/agy.ts`, `pi-extension/subagents/session.ts`).

## Name safety

Omitted runtime names are auto-suffixed across running, in-flight, and registered sessions. Explicit names are trimmed and rejected on collisions before launch, so registry entries and name-only routing cannot become ambiguous. Registry reads validate names and entries, and writes use own data properties so special names such as `__proto__` remain persistent handles instead of mutating object prototypes (`pi-extension/subagents/index.ts`, `pi-extension/subagents/session.ts`).

## Resume safety

New Pi profile launches persist a strict version 2 `mcp-capabilities` snapshot containing selected built-ins, ordered canonical profile extension paths, explicit spawning state and targets, ordered non-secret MCP references/support state, and the existing model, identity, cwd, and agent-directory state. New launch and resume share snapshot-driven command construction and source/digest preflight before pane creation, including explicit empty nested-agent deny-all (`pi-extension/subagents/index.ts`, `pi-extension/subagents/session.ts`).

Snapshot parsing is a strict union. Reject unknown, mixed, incomplete, malformed, duplicate, relative, non-canonical, capability-inconsistent, or nesting-inconsistent version 2 snapshots. Resume re-reads each exact stored MCP source and refuses changed, missing, disabled, invalid, or source-mismatched entries with fresh-spawn guidance. Existing valid version 1 extension-grant and legacy `toolAllowlist` snapshots remain separate compatibility shapes and replay through their unchanged command paths without automatic rewriting (`pi-extension/subagents/session.ts`, `pi-extension/subagents/mcp-config.ts`).

Pi resume never re-reads profiles or package settings and preflights exact stored paths. AGY likewise replays only a strict snapshot containing its exact conversation ID, cwd, model, effort, identity, logical/native tools, generated-agent content, and in version 2 its ordered additional workspace roots; drift or missing state fails before pane creation, and successful continuation atomically updates only the conversation ID. Existing valid version 1 AGY snapshots remain an exact legacy shape and resume without gaining the current parent cwd. Canonical state or session paths are reserved while launching. Finished Claude children are not resumable (`pi-extension/subagents/agy.ts`, `pi-extension/subagents/index.ts`).

A running, exhausted, or failed chain uses a separate strict registry tag and package-owned sidecar. No losing native session or snapshot is addressable through the logical name. A successful target atomically replaces chain ownership with that exact native entry; if replacement fails, the result remains deliverable with an explicit non-resumable warning. Winner continuation is native and never falls back (`pi-extension/subagents/model-chain.ts`, `pi-extension/subagents/session.ts`, `pi-extension/subagents/index.ts`).

## Shell and live-input boundaries

- Build shell commands through `shellEscape`, and use `sendLongCommand` for generated launch scripts (`pi-extension/subagents/tmux.ts`, `pi-extension/subagents/index.ts`).
- Live Pi and Claude messages are not shell commands. Normalize them in the caller, load them into a UUID-qualified tmux buffer through stdin, paste with application-negotiated bracketed framing and deletion, then send Enter separately. Never regress live text to a shell argument or a large `send-keys -l` burst (`pi-extension/subagents/tmux.ts`, `pi-extension/subagents/index.ts`).
- tmux command success proves submission, not child consumption. Confirm waiting Pi delivery only from newer same-child activity; otherwise report submitted or unconfirmed. Never automatically replay or kill after an ambiguous timeout (`pi-extension/subagents/index.ts`, `pi-extension/subagents/activity.ts`).
- Treat child `agent_end` as a recoverable low-level run boundary, never as final completion. Cache its latest messages and keep activity writable so automatic retry, compaction recovery, or queued continuation can replace a transient error. Only `agent_settled` may finalize auto-exit, after rechecking pending questions, running nested children, Pi-owned pending messages, and abort state (`pi-extension/subagents/subagent-runtime-control.ts`, `pi-extension/subagents/activity.ts`).
- A transient capture failure does not establish pane loss. Confirm absence before releasing the running entry; preserve Pi resume registration and keep termination or replay operator-controlled (`pi-extension/subagents/tmux.ts`, `pi-extension/subagents/index.ts`).
- Generated task, system-prompt, and resume-message artifacts include a per-launch UUID after the sanitized runtime-name slug so concurrent distinct names cannot overwrite one another's content (`pi-extension/subagents/index.ts`).
- A `cli: claude` profile invokes `claude --dangerously-skip-permissions`. Only explicitly trusted profiles should enable this path (`pi-extension/subagents/index.ts`).
- AGY tasks and resume messages are private files; the launch script uses escaped paths and a quoted command substitution, so prompt contents are data rather than executable shell syntax. Running AGY messages are rejected before tmux input (`pi-extension/subagents/agy.ts`, `pi-extension/subagents/index.ts`).

## Session replacement and stale context

Pi invalidates an extension instance's `ExtensionContext` and `ExtensionAPI` after `/new`, `/resume`, `/fork`, and `/reload`: every getter and `pi.sendMessage` then throw. Shutdown handlers run before that invalidation, and each replacement loads a fresh module instance. An exception from a message renderer's `render()` is uncaught, so it crashes pi (`pi-extension/subagents/index.ts`, `wiki/raw/2026-11-10-stale-ctx-crash-in-subagent-result-renderer.md`).

- Message renderers and async callbacks must not read a captured `ctx` or `pi` getter. Capture plain objects at `session_start` instead; for example, the `subagent_result` gauge uses the raw model registry captured there, which pi does not invalidate.
- `session_shutdown` first marks the instance as shut down and clears `latestCtx` and `latestPi`, then runs the existing cleanup. Widget updates and question notifications then do nothing.
- Late watcher and chain results are delivered through `deliverSubagentMessage`, which skips delivery after shutdown and contains a throw from a stale API. Results cancelled by shutdown are not re-delivered to the replacement session; child session files remain resumable.

## Runtime files

Name registries, model-chain sidecars, AGY resume snapshots, and activity snapshots use temp-file rename with strict schema validation. Errors in best-effort metadata writes must not turn into an unrestricted resume; an AGY result may remain delivered but explicitly non-resumable (`pi-extension/subagents/agy.ts`, `pi-extension/subagents/session.ts`, `pi-extension/subagents/activity.ts`).

Activity snapshots carry provider-supplied diagnostic text, so a diagnostic field must never invalidate the whole snapshot. The same read gates the stall watchdog, waiting-reply acknowledgment, and pending-question reconciliation. The child recorder collapses CR/LF runs to one space and truncates `toolCallId`, `toolName`, and `messageEventType` to 200 characters before writing. Cursor-provider tool-call IDs embed a newline (`call-...` newline `fc_..._N`). The parent reader drops an invalid optional diagnostic string; structural fields stay strict, and an `invalid` result names only the failing field. Stalled lines show only `invalid activity` or `no activity`, and status lines may add the validator field name. Raw error text and field values are never displayed (`pi-extension/subagents/activity.ts`, `pi-extension/subagents/status.ts`, `spec/archive/261024-1918-fix-false-stalled-status-from-invalid-activity-snapshots/plan.md`).
